# 生活手记 · Layla 中文生活看板

版本：0.3.0。使用官方 `@layla-network/sdk` 7.6.2。

这是运行在 Layla 内的中文小应用。角色在原生聊天中继续对话，小应用管理生活时间线、生成日记／梦境／反思／短作品，支持通过**角色卡受控实时状态块（方案一）**与**独立归档会话 + 原子知识图谱长期记忆（方案二）**协同维护日常作息一致性。不注册聊天拦截，不向聊天记录插入隐藏消息，也不发送主动消息。

## 0.3.0 日常日程引擎升级、独立分表存储与提示词缓存保护

借鉴 `dsh-daily-schedule` 的日程多样性与提示词缓存保护思路，本版对日程生成、存储、角色卡同步块与全量导出规范进行了系统升级：

- **同步块精确度优化与缓存保护**：将角色卡实时状态同步块的时间默认按半小时（`halfhour`）或按节点（`node`）取整；同一节点与睡眠阶段内多次刷新时，同步块文本与哈希保持稳定，跳过无效的 `characters.update()`，保护宿主提示词缓存。
- **日程类型与最近 3 天上下文**：引入带权重、工作日／周末适用范围与引导词的 `dayTypes`（上班日、休息日、外出日、宅家日、加班日、摸鱼日），生成日程时自动注入最近 3 天日程摘要、当天特别要求（`hint`）与固定设定（`extraRules`）。
- **规范化修补与分类模板兜底**：在日程校验前执行 `normalizeItems`（排序、去重叠、补空档以连续覆盖 `00:00–24:00`）；当日生成失败按所选日程类型模板兜底，次日预生成失败则记录冷却延迟重试。
- **晚间预生成次日日程与傍晚预告**。在「生活设置」同时开启后台生活整理与「预生成次日日程」。晚间取得后台执行机会时生成次日框架（默认 `22:00` 后），已有次日计划时复用。傍晚同步块可显示已保存的明日安排。
- **独立 `ll_plans` 表、区间覆盖与旧存档自动升级**：新建独立 `ll_plans` 表存储每日日程的标题、心情、日程类型与 `changes` 变更流水，支持 `applyChange` 区间截断／拆分覆盖；读取旧版（Schema v2）存档时自动将 `profile.plans` 无损迁移至 `ll_plans` 并升级至 Schema v3。
- **说话方式与正事优先规则**：同步块末尾支持可配置的自然口吻说明（支持 `{角色名}`、`{称呼}` 替换，杜绝“按照日程”或机械报时段）、强制“正事优先”原则以及睡眠阶段简短困意回复提示。
- **导出格式规范升级（`specVersion: 1.1.0`）**：全量导出 ZIP 与降级 JSON 新增 `schedules/plans.json`，配套 `EXPORT_FORMAT_SPEC.md` 同步升级至 `1.1.0`（`appVersion: 0.3.0`）。

## 0.2.3 全量生活记录备份与原子级配套格式规范

针对跨平台迁移与长周期角色数据保全需求，本版对“生活设置 → 导出生活记录”进行了全量重构，并随应用分发独立的原子级数据规范文档：

- **全量生活记录备份（R1）**：
  - **结构化 ZIP 归档优先与优雅降级**：内置纯 JS 内存 ZIP 打包引擎（Store 压缩与标准 CRC32 校验），一键打包当前选中角色的完整生活档案。在无法生成二进制归档的环境下，自动平滑降级为单个完备的结构化 JSON 备份文件。
  - **完整数据覆盖**：导出档案完整收录当前角色的 Profile 设定与头像、日常日程与生理事实（`schedules/`）、日记／梦境／反思等原文与摘要（`documents/`）、所有历史细化生活场景片段（`scenes/`）、历史运行记录（`runs/`，移除既有 20 条限制，实现全量抽取）、全局实体与关系三元组（`knowledge-graph/`）以及通过官方 SDK 实时关联读取的原生记忆快照（`native-memories/`）。
  - **标准化清单（manifest.json）**：记录导出版本、规范版本（`specVersion: 1.0.0`）、时间戳、角色唯一标识、应用版本号（0.2.3）及各模块数据统计与文件索引。
- **原子级配套格式规范文档（R2）**：
  - 随应用发布根目录规范文档 `EXPORT_FORMAT_SPEC.md`（构建时自动同步至 `dist/` 并打包进发布 ZIP）。
  - 对标主流记忆底座（Mem0、Letta、Zep 等）的设计范式与通用迁移需求，提供原子级（不可再分）字段 Schema 说明、数据类型、必填性、枚举值、业务语义解释及底座映射指南。
  - 提供详尽规范与真实样本，第三方智能体无需依赖本项目源码即可开发零歧义的数据转换与迁移工具。

## 0.2.2 双轨协同修复：实时作息同步与长期记忆召回增强

针对“日记摘要记录了 8:44 起床，但原生对话中角色仍猜成 9 点或 10 点起床”的问题，本版在互不冲突的前提下同步落地两套机制：

- **方案一（当日确定性作息同步）**：开启“生活设置 → 同步今日作息与摘要到角色卡指令”后，小应用在更新生活、生成场景、调整日程或整理日记时，通过 `characters.update()` 在角色卡 `post_history_instructions` 末尾原位维护一段由 `【生活手记·实时状态】…【/生活手记·实时状态】` 包裹的当日作息快照（包含起床／首个清醒片段时间、当前活动、今日已记录片段与今日日记／梦境简摘）。
  - 保留角色卡原有 `post_history_instructions` 与全部设定字段；关闭开关或点击“清除角色卡同步块”可无损移除同步块。
  - 小应用读取角色卡时自动剥离该同步块（`stripCardSyncBlock`），不参与 `sceneIdentity` 哈希计算，杜绝缓存抖动与自我复读回环。
  - 同步块带有明确记录日期标记，随每日刷新原位覆盖，不会无限膨胀。
- **方案二（跨会话与次日长期记忆召回重构）**：
  - **独立归档会话（避开同会话近期屏蔽）**：默认将长期记忆写入独立归档会话 `life-archive-<characterId>`（可在设置中切回绑定当前原生会话），避免宿主 LTM 因“假定当前聊天上下文已包含同会话近期内容”而跳过刚交还的日记。
  - **原子单次写入与自动回退**：`writeMemory` 在 `id: 0` 首次创建前先生成知识图谱，单次 `memories.createOrUpdate()` 同步提交正文、带时间锚点的摘要与 `knowledgeGraphJSON`，避免二次更新导致的宿主索引滞后；若宿主忽略首次图谱则自动复用草稿补写同一正 ID，若模型图谱校验失败仍保留纯文本记忆供后续重试。
  - **角色一跳日期作息图谱 + 梦境／创作二跳隔离**：扩充时间与作息关系，支持 `08:44` 与 `8:44` 等时间空白归一化原文核对；对日记与反思自动建立 `角色名 -> YYYY-MM-DD作息/时间/动作/地点` 的一跳三元组，提升按角色与作息提问时的图谱命中率；对梦境与创作继续严格维持二跳节点隔离（`梦境，不是现实事件`／`创作作品，不是现实事件`），不污染现实事实。
  - **统一时间线事实源与同日原位重整**：方案一与方案二共用 `dailyTimelineFacts()` 提取起床时间与活动锚点；当天归档支持在阅读窗口点“重新整理”并原位更新既有原生记忆编号，不产生重复条目。

## 0.2.1 记忆图谱补全修复

本版针对“梦境文本存在，但原生聊天自然询问时答成另一场梦”的现象，补全记忆加工阶段；不宣称已经解决宿主召回问题。

- 新记录交还分为“保存文本 → 模型提取图谱 → 更新同一原生记忆 ID → 回读核对”。图谱采用开发者 LLM-LTM 项目的 `subject / relationship / object` 三元组格式。
- 图谱将角色连接到带日期和标题的记录节点。梦境细节只挂在该梦境下，关系名使用“梦中地点／梦中声音”等；作品同理，不把内容写成现实经历。细节对象必须逐字出现在原文或摘要中，结构与来源检查仍不能证明所有语义均正确。
- “记忆交还”页增加逐篇“补全图谱”。0.2.0 已写入记录会显示“旧记录待补全”；未卸载且宿主保留私有数据库时可直接修复。仅处理本小应用归档中有来源标记的记忆，不扫描修改其他原生记忆。
- 使用已记录的原生记忆 ID 更新，保留原生原文、摘要、时间与会话归属。已存在的可解析图谱只核对，不覆盖；原文在模型生成期间发生修改时停止更新。SDK 没有条件更新接口，最后一次核对与提交之间仍有极短竞争窗口；补全过程请避免同时编辑该条原生记忆。
- 图谱草稿单独保存。模型格式错误／停止时保留文本，手动重试；更新回执丢失时先回读核对，不重复创建记忆。原文或图谱发生变化会保留用户编辑并要求重新核对。
- 已写入文本、原生图谱已核对、用户召回验收结果分开显示。图谱“已核对”仅表示字段可解析并从宿主读回，不代表索引构建或本轮聊天注入已确认。
- “记录召回验收”仅保存用户报告；选择通过需确认在未贴原文的新会话中测试。修改图谱或核对到来源变化时重置为尚未验收，最近十条报告保留在导出中。浏览器演示的手动通过也只是示例用户报告。
- 新交还每篇增加一次图谱模型调用；后台对新内容执行同样流程，旧记录不批量补写。图谱失败后由你在前台重试，避免后台反复调用模型。
- 天气维持手动记录；本次只修复记忆加工。

### 0.2.0 用户升级与旧梦境修复

1. 在旧版“生活设置 → 导出生活记录”保存备份。
2. 导入 `layla-life-dashboard-zh-0.2.1.zip`，更新同名 `Layla Life Dashboard`；不要先卸载。覆盖安装是否保留私有数据由宿主决定。
3. 进入“记忆交还”，找到已有梦境，核对原生记忆编号，点“补全图谱”。这一步更新原条目，不新增梦境。
4. 等到“原生图谱已核对”，展开“查看已核对图谱”，并在 Layla 长期记忆界面复核。
5. 用一条从未贴入聊天的新记录测试自然召回。已经粘贴原文的旧梦境会受到聊天上下文和新生成记忆影响，不适合作为唯一验收样本。
6. 将真机结果记到“记录召回验收”。若仍失败，保留 Layla 版本、原生记忆编号、图谱、问句和回复；公开 SDK 不提供本轮召回轨迹或索引完成回执，后续需要宿主侧证据。

“核对写入”只恢复文本回执，不暗中再调用模型；确认后可继续“补全图谱”。找不到已记录的原生 ID 时不会自动创建替代条目。日期被手动改到原时间窗以外的记忆需先在 Layla 中核对，当前查找范围为记录时间前后一分钟，分页最多一千条。

## 0.2.0 当前生活场景

- 将全天日程框架和当前场景细化拆开。生成日程时不预写未来经历；到达当前节点后，单独调用模型描写约 150–250 字的场景。
- 场景参考现有角色卡的描述、性格与场景，结合当前时间、节点、睡眠阶段、生活状态、有效天气记录和前两个已记录片段。场景提示还参考最近四条原生消息和最多四条重要记忆，并进一步裁剪长度。
- “当前活动”和“细化场景”读取同一段完整文字；首页顶部只展示短预览。日程页新增“已记录的生活片段”。
- 按角色、当地日期、节点内容、角色卡摘要、睡眠阶段与叫醒窗口缓存。普通刷新复用缓存，进入新节点、入睡／浅睡／深睡／被叫醒阶段变化时才生成新场景；被叫醒后再次入睡会生成新的片段。
- 默认开启“生活设置 → 自动细化当前场景”。打开看板、前台节点切换、返回应用以及获得后台执行机会时检查。关闭后仍可手动生成；手动填写的场景会保留。
- “重新生成场景”明确创建新版本，旧版本仍留在片段记录中。生成可停止，JSON 或长度不合格时保留旧内容；首次生成失败后，自动重试至少间隔十分钟。普通刷新不会用失败占位文本冒充经历。
- 场景生成不会修改精力、位置、睡眠阶段等规则状态；提示词要求叙事服从这些条件。结构校验不能代替模型语义判断，真实模型的描写一致性仍需观察。
- 场景从实际生成／记录时开始归档，不倒填节点开始以来的空白，也不补造离线时段的细节。日记只参考当天已记录片段，当前活动按生成日记的截止时刻截断，不把未来计划写成已完成经历。
- 场景只保存在小应用中。日记／梦境等仍经“交还 Layla”写入原生记忆；不向每轮原生聊天注入生活提示。

## 安装与首次使用

1. 在 Layla 的 Apps／小应用管理中导入 `layla-life-dashboard-zh-0.3.0.zip`。ZIP 根目录就是 `app.json`、`index.html`、`task.js` 和图标，不要再套一层目录。
2. 打开“生活手记”，选择已有角色。新角色若没有原生会话，请先在原生界面聊一轮，再回看板点“更新生活”。
3. 到“生活设置”确认时区、作息、默认位置，并手动记录天气和健康备注。默认日程是明确标识的作息模板；可在“日程流转”生成符合角色设定的今日日程。开启自动细化时，当前节点会调用 Layla 已配置的模型生成场景。
4. 在“日记与梦境”生成内容，阅读正文和摘要后点“交还 Layla”。默认不自动写入记忆。
5. 核对文本、图谱分别完成后返回原生聊天测试自然召回；“原生图谱已核对”不表示索引或召回已经验证。

手机宿主需要支持 SDK 中的角色、会话历史、记忆读写和私有 SQLite 接口；仅升级 npm 包不能给旧宿主增加能力。首次出现接口错误时请保留看板中的错误信息与 Layla 版本号。

直接在普通浏览器打开 `index.html` 会进入清楚标记的演示模式，使用官方 SDK mock、固定生成样例和独立浏览器数据。演示不会连接你的实际角色，不需要 API Key。

## 看板字段

| 区域 | 字段 |
| --- | --- |
| 正在做的事 | 睡眠阶段、当前活动、所在位置、心情、天气、健康备注 |
| 日程流转 | 当前节点、时间窗、节点类型、细化场景、下一节点、下一节点开始、日期类型、近期节日 |
| 生活状态 | 精力、饥饿、心情愉悦度、活跃度 |
| 内容与记忆 | 日记、梦境、反思、创作、正文、摘要、回写状态、原生记忆编号 |

所有生活状态都属于角色模拟。天气是手动记录，标有更新时间，超过六小时会提示记录较旧；不伪装成联网天气。公历节日及设备支持的农历日期只作日历提示，不推算法定假期与调休。支持北京时间、日本时间和 UTC，三者不涉及夏令时，后台 QuickJS 无 Intl 时仍可正确定位时间。

## 日程和睡眠行为

- 日程节点连续覆盖 00:00–24:00，检查空档、重叠、无效时间与类型。可手动编辑各节点。
- 生成、手动编辑和区间调整统一保存到 `ll_plans`。读取旧 Profile 时导入缺少独立记录的日程，以分表中的已有记录为准。
- 「日程流转 → 记录起床时间」可按角色与生活日期确认实际起床时间。计划结束休息、首个清醒片段与确认的起床时间分别保存。已归档文稿保留生成时的时间来源，当日可通过「重新整理」采用更新的确认记录。
- 数值按经过时间推进，最多补算最近 72 小时。补算不是后台持续思考，也不补造早期聊天。
- 睡眠阶段只反映生活时间线。若读到角色在休息期间的实际原生回复，会记录 30 分钟的模拟清醒窗口；不会限制原生回复。
- 用户发来消息本身不等于角色已醒；按实际 assistant 消息判断。
- 改作息只影响作息模板。已经生成或手动编辑的今日日程，需要重新生成／编辑才能改变。

## 内容生成与记忆交还

生成时读取最近最多 20 个会话的目录，从选定会话及最近会话合计最多 3 个会话、每个最多 60 条消息读取上下文。重要记忆取宿主排序后的最多 10 条；模型上下文再做长度裁剪。这不是全量历史分析。

角色已有描述、性格、场景、用户 Persona、生活状态及原生对话参与生成。角色资料和聊天是参考数据，不作为任意操作指令。没有可用模型或结果不合格时显示错误，保留原内容，不用占位文本冒充模型输出。前台生成支持流式进度和停止。

每个角色每天每类内容至多一篇。日记的生活来源只使用已记录的当日片段，并保留片段 ID 与整理截止时间；梦境、反思和创作可参考近期片段。空白时段不会根据计划补造。日记上下文最多采用当天最近 100 个片段，其他内容采用最近 12 个片段，界面展示当天最近 8 个片段。原始正文留在小应用，写入记忆的正文包含来源、日期、内容类型与唯一标记；梦境和创作明确区分现实事件。重复生成直接打开已有内容。暂不支持同一天重写或删除归档。

记忆先使用 `memories.createOrUpdate()` 新增文本并保存宿主 ID，再提取兼容三元组，通过相同正 ID 更新 `knowledgeGraphJSON` 并回读核对。每次创建前，按记录时间窗与唯一标记核对已有记忆。如果写入途中失去回执，保留“待核对”并停止自动重发，避免重复记忆；可点“核对写入”重新检查。若始终不能核对，请检查原生记忆管理，当前版本不强制重发。

不会把之前生成的生活记忆重新作为“真实经历证据”送回生成器。背景自动写入默认关闭。首次部署应先验证一条包含独特作品名的记录能否在原生聊天召回；官方说明最近的同会话记忆可能被召回策略暂时跳过，也应测试新会话。

## 后台任务

先在本应用“生活设置”开启角色的后台整理，再在 Layla 任务管理器中启用本应用。仅设置看板开关并不能启动系统后台任务。

- 每轮处理一个已启用角色，更新状态；最多生成一个当前场景和一篇文稿，二者都复用已有缓存。
- 达到设定的日记小时后整理今日日记；其他时段，在观察到至少三小时夜间睡眠结束后的六小时内，可整理当天梦境。
- 每类每天幂等，不重复生成。启用“自动交还新记录”后，才会在后台回写新内容并补全图谱。每篇新增一次图谱生成，失败保留文本，前台可重试。
- 状态与记录保存在同一小应用 SQLite，前台／后台按角色加互斥租约；长任务异常的租约最长保留 30 分钟。
- `task.js` 使用宿主注入的全局 `layla`，没有运行时 import、DOM、fetch、计时器或常驻循环。最后一个表达式返回任务 Promise。
- iOS 后台时间由系统和 Layla 宿主决定；可能延迟到下一次执行，不能承诺精确时间或杀掉 App 后继续生成。

## 导出

“生活设置 → 导出生活记录”导出当前角色的生活设置、状态、全部日程、全部场景版本、归档正文和近期运行记录。单篇阅读窗口支持导出 Markdown。通过 Layla 原生分享面板交给其他应用。当前版本提供导出，不含导入恢复界面。

## 开发

Node.js 22.13 或更新版本。SDK 与构建依赖均锁定版本。

```bash
npm ci
npm test
npm run build
npm run serve
```

浏览器打开本地服务器即可预览。交付 HTML 已包含样式、脚本与 SDK，无 CDN 依赖。

`npm run test:ui` 需要 Playwright 与 Chromium；在 Codex 环境使用已安装的运行时 Playwright，普通环境可自行安装。源码里的测试包含真实 SQLite 存取、跨日作息、回写去重、回执丢失恢复、后台任务及移动端界面检查。

项目结构：`src/memory.js` 为记忆保存、图谱补全与恢复流程，`memory-graph.js` 为图谱格式校验，`model.js` 为前后台共用模型调用；`src/core.js` 为纯生活计算；`store.js` 为私有存储与锁；`workflow.js` 为角色读取、独立场景生成、文稿整理和回写；`main.js` 为中文界面；`demo.js` 为独立演示环境；`task-entry.js` 为后台入口。
